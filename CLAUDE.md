# Работа с репозиторием

Прогнозирование энергопотребления Smart Grid и управление накопителем. Курсовая
доводится до дипломной работы. Рабочая ветка — `feature/panel-data-v2`.

Навигация по документации:

| Файл | Что внутри |
|---|---|
| `README.md` | Методика, режимы запуска, измеренные результаты |
| `CHANGELOG.md` | История правок и найденных дефектов, сверху новые |
| `docs/ARCHITECTURE.md` | Карта модулей, потоки данных, инварианты, раскладка артефактов |
| `docs/ROADMAP.md` | Этапы улучшения с чек-листами и текущим статусом |
| `docs/RESULTS.md` | Какие прогоны стоят за каждой цифрой и актуальны ли они |
| `docs/archive/` | Устаревшие планы и черновики, хранятся для истории |

## Команды

Перед запуском python в Git Bash:

```bash
export PYTHONIOENCODING=utf-8
```

Тесты. Без переменной pytest падает на стороннем плагине `importnb`:

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python -m pytest tests/ -q
```

Проверка работоспособности, около минуты каждая:

```bash
python main.py --mode smoke --seed 0
python main.py --mode panel-smoke --seed 0
python main.py --mode panel-smoke --dataset uci --seed 0
```

Длительность полных режимов на этой машине:

| Режим | Время |
|---|---|
| `optimal` | ≈ 52 мин, без нейросетей ≈ 4 мин (`--models naive24,profile,ridge,xgboost`) |
| `panel-fast` | 7–25 мин на сид |
| `panel-fast --probabilistic` | ≈ 35–55 мин |
| `panel-optimal` | 24–57 мин на сид |
| `full` | несколько часов |

## Git

- Push только через порт 443, порт 22 закрыт:
  `git push ssh://git@ssh.github.com:443/BRIGHTSIDEq/smartgrid.git feature/panel-data-v2:feature/panel-data-v2`
- `gh` установлен, но не авторизован.
- В начале каждой сессии проверять `git branch --show-current`: рабочее дерево уже дважды оказывалось на `main`.
- Файлы с CRLF сохранять с CRLF: правки делать скриптом, который читает `newline=""` и восстанавливает окончания строк.

## Правила, заданные владельцем проекта

- Не удалять существующие результаты в `results/`. Изменённые и новые файлы там считаются пользовательскими.
- Не использовать `git reset --hard`.
- Не сливать в `main` без подтверждения.
- Долгие прогоны (`optimal`, `full`, `panel-optimal`, многосидовые серии) запускать только с подтверждения владельца.
- Коммит и push в рабочую ветку — только после прохождения тестов и smoke-проверки.

## Принятые в проекте соглашения

- Комментарии и docstring на русском и объясняют, почему сделано так, а не что делает код.
- Каждый исправленный дефект закрывается тестом, который падает на старом коде. Проверять это мутацией: откатить правку и убедиться, что тест упал.
- Не менять код конвейера, пока идёт серия прогонов на нескольких сидах: следующие сиды получили бы другой код, и результаты стали бы несопоставимы.
- Цифры в README брать из каталогов прогонов `results/runs/*/`, а не из сводных файлов в корне `results/`. Сводные файлы пока ненадёжны (см. `docs/ROADMAP.md`, этап 1).
- Отбор моделей и параметров решающего правила — только по валидации. Тест используется один раз.
- Отрицательные результаты и отозванные выводы фиксируются в CHANGELOG, а не удаляются.
