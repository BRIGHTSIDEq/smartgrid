# Smart Grid — прогнозирование энергопотребления и оптимизация накопителя

Курсовая работа: сравнение архитектур машинного обучения для почасового
прогнозирования агрегированного энергопотребления города и оценка
экономического эффекта батарейного накопителя, управляемого по прогнозу.

**Автор:** Ruslan Khismatov
**Научный руководитель:** А.А. Агафонов

---

## Что делает проект

1. **Генерирует** синтетический почасовой ряд потребления города с физически
   осмысленными компонентами: погода, поведенческие профили домохозяйств,
   районная структура, электротранспорт, распределённая солнечная генерация,
   промышленность, события управления спросом, праздники РФ.
2. **Прогнозирует** потребление на 24 часа вперёд семью моделями — от наивных
   базлайнов до трансформеров.
3. **Сравнивает** их корректно: с наивной точкой отсчёта, метрикой MASE,
   разрезом по шагам горизонта и проверкой статистической значимости.
4. **Оптимизирует** работу накопителя ПО ПРОГНОЗУ модели и измеряет, во сколько
   рублей обходится ошибка прогнозирования.

## Быстрый старт

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

Проверка работоспособности (около минуты):

```bash
python main.py --mode smoke --skip-eda
```

Команда работает как есть, в том числе в русской Windows: задавать
`PYTHONIOENCODING` или менять кодовую страницу консоли не нужно.

Рабочий прогон:

```bash
python main.py --mode optimal
```

Результаты появятся в `results/`: графики в `plots/`, сводные таблицы в
`metrics.csv` и готовые к вставке в записку таблицы в `markdown_tables.md`.

## Режимы и параметры запуска

| Флаг | Значения | Назначение |
|---|---|---|
| `--mode` | `smoke`, `fast`, `optimal`, `full`, `panel-smoke`, `panel-fast`, `panel-optimal` | Объём данных и глубина обучения |
| `--seed` | целое | Сид генератора случайных чисел |
| `--models` | `all` или список через запятую | Какие модели обучать |
| `--scenario` | `current`, `forward` | Проникновение технологий Smart Grid |
| `--rolling-origin` | N | Walk-forward бэктестинг с N переобучениями |
| `--skip-eda` | — | Пропустить исследовательский анализ |
| `--skip-storage` | — | Пропустить блок накопителя |
| `--skip-attention` | — | Пропустить визуализацию внимания |
| `--deterministic` | — | Детерминированные операции TensorFlow |

Режимы:

| Режим | Данные | Эпохи | История | Время на CPU |
|---|---|---|---|---|
| `smoke` | 40 дней, 60 домов | 2 | 48 ч | ~1.5 минуты |
| `fast` | 365 дней, 250 домов | 120 | 48 ч | ~1–2 часа |
| `optimal` | 730 дней, 2500 домов | 240 | 48 ч | **5–8 часов** |
| `full` | 730 дней, 2500 домов | 320 | 192 ч | сутки и более |

Оценки измерены на 12-ядерном CPU без GPU (одна эпоха на данных `optimal`:
LSTM 51 с, PatchTST 62 с, VanillaTransformer 135 с). Верхняя граница `optimal`
без ранней остановки — около 16 часов; фактическое время определяется тем, на
какой эпохе сработает EarlyStopping (`PATIENCE = 25`).

Ускорить можно тремя способами, каждый меняет условия эксперимента и должен
быть оговорён в работе: уменьшить `EPOCHS`, обучать подмножество моделей через
`--models`, либо запускать на машине с GPU.

Ключи моделей для `--models`: `naive24`, `naive168`, `profile`, `ridge`,
`xgboost`, `lstm`, `transformer`, `patchtst`.

**Сценарии проникновения технологий** (`--scenario`). Влияют только на
генератор данных и всегда фиксируются в метаданных прогона:

| Сценарий | Электромобили | Микрогенерация | Смысл |
|---|---|---|---|
| `current` (по умолчанию) | 0.5% домохозяйств | 0.2% | Фактическое состояние РФ, 2025 |
| `forward` | 15% | 3.0% | Перспективный сценарий |

При `current` распределённые ресурсы почти не влияют на профиль нагрузки — это
и есть реальность. Раздел работы о влиянии Smart Grid имеет смысл считать по
`forward`, явно оговаривая, что это проекция, а не измерение.

Каждый прогон пишет результаты в отдельный каталог
`results/runs/<дата>_<режим>_<сценарий>_seed<N>/` вместе с метаданными
(коммит git, версии библиотек, размеры выборок, выбранная по валидации модель),
поэтому старые результаты не перезаписываются и не смешиваются с новыми.

Оценка разброса по сидам — три прогона подряд, результаты дописываются
в `results/metrics.csv` и агрегируются автоматически:

```bash
python main.py --mode fast --seed 0 && python main.py --mode fast --seed 1 && python main.py --mode fast --seed 2
```

### Ценность прогноза для накопителя

Сглаживание пика, годовые величины в рублях:

| Источник прогноза | MAE | Валовая экономия | Чистая экономия | Пик после | Окупаемость |
|---|---|---|---|---|---|
| Идеальный прогноз | — | 346 783 | 242 001 (3.7%) | 1608 кВт | 14.5 лет |
| XGBoost | 68.8 | 133 160 | 37 066 (0.6%) | 1824 кВт | 94 года |
| Naive24 | 125.2 | 40 341 | **−48 774** | 1914 кВт | никогда |

Три вывода, каждый из которых важнее самой точности прогноза:

Ошибка прогноза уничтожает **85%** ценности сглаживания пика: 242 тысячи
превращаются в 37. Плата за мощность — статистика максимума, а промах по
одному часу обесценивает работу за весь месяц.

С наивным прогнозом накопитель **приносит убыток**: пик не снижается вовсе
(1914 кВт до и после), а деградация ячеек оплачивается. Ценность прогноза здесь
не в улучшении на проценты, а в различии между прибылью и убытком.

Даже при идеальном прогнозе окупаемость 14.5 лет превышает типичный ресурс
батареи. Сглаживание пика в отдельности не оправдывает установку при текущих
ценах — это отрицательный результат, и он получен честно.

## Многорядный режим (panel)

Агрегатный режим возвращает один ряд города, и увеличение числа домохозяйств
не добавляет обучающих данных: растёт только масштаб, а коэффициент вариации
даже падает. Panel-режим формирует несколько городов, в каждом несколько
фидеров со своими параметрами, и обучает **одну глобальную модель на всех
рядах сразу**.

```bash
python main.py --mode panel-smoke --seed 0
```

| Режим | Города × фидеры | Дней | Рядов | Окон train | Время |
|---|---|---|---|---|---|
| `panel-smoke` | 1 × 4 | 90 | 4 | 5 764 | ~1.5 мин |
| `panel-fast` | 2 × 8 | 365 | 16 | 96 976 | ~20 мин |
| `panel-optimal` | 4 × 24 | 1095 | 96 | ~1.7 млн | **не запускается** |

`panel-optimal` намеренно отказывается стартовать: при материализации всех
окон в памяти требуется порядка десятков гигабайт. Конвейер оценивает объём
до генерации данных и прерывается с ненулевым кодом, чтобы не исчерпать
память посреди расчёта. Для этого режима нужна потоковая подача (`tf.data`),
которая пока не реализована.

**Три группы входов.** Модели получают историю ряда, точно известный календарь
целевого окна и статические характеристики фидера. Погода на будущее подаётся
только прогнозом с ошибкой, растущей по горизонту: фактической будущей погоды
в эксплуатации не существует, и её использование завысило бы качество.

Одинаковый набор входов получают все модели, включая Ridge и градиентный
бустинг — иначе разрыв в метриках отражал бы разницу в объёме входной
информации, а не в способностях моделей.

**Метрики панели.** Усреднённое MAE вводит в заблуждение: крупные фидеры
доминируют и скрывают качество на мелких. Поэтому считаются micro (по всем
окнам), macro (среднее по рядам) и худший ряд. Городской прогноз строится
суммированием фидеров, а не отдельной моделью, поэтому согласованность
иерархии измеряется напрямую.

### План 2×2: объём данных против их природы

MASE на тесте. Строки — модели, столбцы — четыре сочетания «размер панели ×
источник данных».

| Модель | синт. 16×1г | синт. 96×3г | UCI 16×1г | UCI 96×3г |
|---|---|---|---|---|
| XGBoost | **0.596** | **0.568** | **0.926** | **0.874** |
| DLinear | 0.660 | 0.604 | 0.974 | 0.895 |
| Ridge | 0.664 | 0.663 | 1.134 | 0.987 |
| HourlyProfile | 1.340 | 0.888 | 1.640 | 1.958 |
| Naive24 | 1.039 | 1.009 | 1.151 | 0.995 |

**Разрыв между нейросетью и линейной моделью.** DLinear минус Ridge:

| Ячейка | Разрыв | Вывод |
|---|---|---|
| синтетика 16×1г | −0.005 | неразличимы |
| синтетика 96×3г | −0.059 | DLinear лучше |
| UCI 16×1г | −0.160 | DLinear лучше |
| UCI 96×3г | −0.092 | DLinear лучше |

DLinear выигрывает в трёх ячейках из четырёх. Единственная ничья — малая
синтетическая панель, то есть ровно та постановка, по которой напрашивался
вывод «нейросеть не окупает свои 86 680 параметров». Вывод, сделанный по одной
слабейшей ячейке, оказался бы неверным.

**Линейная модель состоятельна только на синтетике.** Улучшение над наивным
прогнозом:

| Ячейка | XGBoost | DLinear | Ridge |
|---|---|---|---|
| синт. 16×1г | +42.6% | +36.5% | +36.0% |
| синт. 96×3г | +43.7% | +40.1% | +34.2% |
| UCI 16×1г | +19.6% | +15.3% | **+1.4%** |
| UCI 96×3г | +12.2% | +10.0% | **+0.8%** |

На реальных данных Ridge практически не отличается от повтора прошлых суток,
тогда как на синтетике даёт треть улучшения. Генератор складывает нагрузку из
аддитивных компонент, и линейная модель разбирает её обратно — на настоящем
потреблении такой структуры нет.

**Климатология ведёт себя противоположно на двух источниках.** На синтетике
переход от одного года к трём улучшает её (1.340 → 0.888): профиль начинает
видеть все сезоны. На реальных данных тот же переход её ухудшает
(1.640 → 1.958). Причина в нестационарности: за три года состав и режим
потребления клиентов меняются, и усреднённый по такому периоду профиль хуже
описывает тестовый отрезок. Генератор этого свойства не воспроизводит —
отдельное указание на то, чего синтетике недостаёт.

**Оговорка.** На UCI моделям доступно 12 исторических признаков против 19 и 7
статических против 12: в наборе нет ни погоды, ни электротранспорта, ни
микрогенерации. Часть разрыва объясняется отсутствием ковариат, а не природой
данных, и разделить эти вклады на имеющемся материале нельзя.

### Три постановки: как выводы зависят от данных

MASE на тесте. Слева направо растёт объём данных, справа — реальные измерения.

| Модель | `panel-fast` синт. | `panel-optimal` синт. | `panel-fast` UCI |
|---|---|---|---|
| | 16 рядов, 1 год | 96 рядов, 3 года | 16 рядов, 1 год |
| XGBoost | **0.596** | **0.568** | **0.926** |
| DLinear | 0.660 | 0.604 | 0.974 |
| Ridge | 0.664 | 0.663 | 1.134 |
| HourlyProfile | 1.340 | 0.888 | 1.640 |
| Naive24 | 1.039 | 1.009 | 1.151 |

**Разрыв между нейросетью и линейной моделью зависит от постановки.**

| Постановка | DLinear − Ridge | Вывод |
|---|---|---|
| `panel-fast` синтетика | −0.005 | неразличимы |
| `panel-optimal` синтетика | −0.059 | DLinear лучше |
| `panel-fast` UCI | −0.160 | DLinear заметно лучше |

На малой синтетической панели DLinear и Ridge неразличимы, и по одному этому
результату можно было бы заключить, что нейросеть не окупает свои 86 680
параметров. Заключение оказалось бы неверным: разрыв появляется и при
шестикратном увеличении панели, и при переходе к реальным данным. На UCI Ridge
даёт всего +1.4% против наивного прогноза, тогда как на синтетике давал +36% —
его состоятельность там во многом была свойством генератора, складывающего
нагрузку из аддитивных компонент.

**Климатология: подтверждение объяснения через эксперимент.** На `panel-fast`
профиль «ряд × день недели × час» проигрывал наивному прогнозу (1.340 против
1.039). Объяснение состояло в том, что при единственном годе хронологическое
разбиение отводит под тест ноябрь–декабрь — сезон, отсутствующий в обучении.
На трёх годах профиль выигрывает у наивного (0.888 против 1.009), а сам
Naive24 приближается к 1.0: тест перестал быть аномально трудным.

**Оговорка к сравнению с UCI.** Там доступно 12 исторических признаков против
19 и 7 статических против 12: в наборе нет ни погоды, ни электротранспорта, ни
микрогенерации. Часть разрыва объясняется отсутствием ковариат, а не сложностью
реальных данных, и разделить эти два вклада на имеющихся данных нельзя.

**Разброс по сидам измеряет разное.** На синтетике сид меняет сами данные, на
UCI данные фиксированы и меняется только обучение. Поэтому у Naive24,
климатологии и Ridge на UCI разброс равен нулю, а у DLinear составляет 0.012.

96 рядов × 1095 дней, окна прорежены шагом 11 → 159 936 обучающих окон.
Прогон занял 28.4 минуты, пик памяти 2.4 ГБ.

| Модель | MASE | MAE | sMAPE | Худший ряд, MAE | Обучение |
|---|---|---|---|---|---|
| XGBoost | **0.568** | 19.87 | 4.61% | 42.3 | 1061 с |
| DLinear | 0.604 | 21.12 | 4.91% | 50.7 | 266 с |
| Ridge | 0.663 | 23.01 | 5.47% | 56.0 | 243 с |
| HourlyProfile | 0.888 | 30.89 | 6.91% | 76.0 | 2 с |

### Измеренный результат: `panel-fast`, три сида

16 фидеров, 365 дней, 96 976 обучающих окон. MASE < 1 означает, что модель
превзошла повтор прошлых суток.

| Модель | MASE (тест) | MAE | худший ряд, MASE | обучение |
|---|---|---|---|---|
| XGBoost | **0.596 ± 0.005** | 19.88 | 0.684 | 705 с |
| DLinear | 0.660 ± 0.043 | 21.90 | 0.748 | 164 с |
| Ridge | 0.664 ± 0.013 | 22.28 | 0.812 | 272 с |
| Naive24 | 1.039 ± 0.016 | 34.69 | 1.143 | — |
| HourlyProfile | 1.340 ± 0.092 | 45.13 | 1.929 | 11 с |

**DLinear и Ridge неразличимы.** Парные разности по сидам меняют знак
(+0.058, −0.042, −0.030), среднее −0.005 при разбросе 0.055. Нейросеть с
86 680 параметрами не превзошла линейную модель — тот же вывод, что у Zeng et
al. (2023), воспроизведённый на собственных данных.

Агрегатный конвейер даёт согласованную картину: LinearRegression 0.656,
XGBoost 0.660, PatchTST 0.713, LSTM 0.728.

**Климатология проигрывает наивному прогнозу на тесте** (1.340 против 1.039),
хотя на валидации выигрывала (0.852 против 1.013). Профиль строится по
«ряд × день недели × час» без месяца и температуры, а при одном годе данных
хронологическое разбиение отводит под тест ноябрь–декабрь — сезон, которого не
было в обучении. Отсюда следует ограничение режима: `panel-fast` измеряет в том
числе экстраполяцию на холодный период. У `panel-optimal` на трёх годах этого
эффекта нет.

**Зачем здесь MASE.** Разброс MAE между сидами у XGBoost — 4.03, разброс
MASE — 0.005. Абсолютная ошибка меняется вместе с размером сгенерированных
фидеров, и на её фоне разрывы между моделями тонут. MASE нормирует ряд на его
собственную сложность, и порядок моделей становится устойчивым.

**Воспроизводимость.** Повторный запуск того же сида в отдельном процессе даёт
побитово совпадающие метрики у всех пяти моделей, включая нейросеть.

### Реальные данные: UCI ElectricityLoadDiagrams20112014

```bash
python main.py --mode panel-fast --dataset uci --uci-path data/raw/LD2011_2014.txt
```

Вывод «линейные модели не уступают глубоким» получен на синтетике, которую
проект генерирует сам. Генератор складывает нагрузку из аддитивных компонент, и
такое устройство благоприятно для линейных моделей — возражение, на которое
можно ответить только данными, созданными не этим проектом.

Набор содержит потребление 370 клиентов Португалии за 2011–2014 годы с шагом
15 минут. Файл **не скачивается автоматически**: загрузка внешних данных —
решение пользователя. Без файла запуск завершается с кодом 1 и указанием, что
и откуда взять.

Оба источника приводятся к одному формату **до** входа в конвейер, и дальше
обработка не ветвится: расхождение сделало бы результаты несравнимыми.

**Что в этих данных устроено неочевидно** — каждый пункт закрыт тестом,
падающим при снятии соответствующей правки:

| Особенность | Последствие без обработки |
|---|---|
| Метка времени — конец интервала | суточный профиль смещён на 15 минут |
| Значения — мощность, не энергия | масштаб завышен вчетверо |
| Мартовский день перевода часов | час нулей у всех клиентов ежегодно |
| Октябрьский день перевода | час с удвоенным потреблением ежегодно |
| Нули до подключения клиента | обучение на несуществующем объекте |
| Праздники — португальские | чужой календарь метит рабочие дни выходными |

Правки дней перевода применяются только при подтверждении ожидаемой картины в
самих данных: слепая коррекция по календарю испортила бы уже исправленный
набор. Каждая правка попадает в отчёт прогона.

Погоды в наборе нет, и она не подставляется синтетической — это вернуло бы
зависимость от собственного генератора. Статические признаки выводятся из
данных по **обучающему отрезку**: посчитанные по всему ряду, они перенесли бы
в обучение сведения о тесте.

**Состав моделей:** Naive24, HourlyProfile, Ridge, XGBoost, DLinear. DLinear —
обязательный базлайн из работы Zeng et al. (AAAI 2023), где показано, что
линейная модель с декомпозицией обходит трансформеры на задачах
долгосрочного прогнозирования.

## Методические принципы

Эти решения определяют, можно ли доверять результатам, поэтому они закреплены
в коде и покрыты тестами.

**Разделение данных строго хронологическое.** Никакого перемешивания: train →
val → test по времени. Все скалеры обучаются только на train и лишь
применяются к val/test — это касается и потребления, и погодных ковариат, и
нагрузки электротранспорта.

**Лучшая модель выбирается по валидации.** Тестовая выборка используется один
раз, для итоговой таблицы. Выбор победителя по тесту сделал бы итоговую оценку
смещённой.

**Наивный базлайн обязателен, ключевая метрика — MASE.** MASE — это MAE модели,
делённый на MAE сезонно-наивного прогноза, посчитанный на обучающей выборке.
Значение ≥ 1 означает, что модель не превзошла «повторить прошлые сутки», каким
бы ни был её абсолютный MAE.

*Замечание об интерпретации:* знаменатель MASE считается по train, поэтому на
более трудном тестовом периоде MASE наивной модели может оказаться больше
единицы — это характеристика периода, а не ошибка расчёта.

**Автокорреляция остатков считается по срезу фиксированного шага горизонта.**
Прогноз имеет форму (N, 24) из окон со сдвигом 1 час. В развёрнутом векторе
соседние элементы относятся к разным моментам времени, и «лаг 24» по нему
равен одному часу реального времени. Корректный почасовой ряд — это
`residuals[:, h]` при фиксированном h.

**Различия моделей проверяются тестом Диболда–Мариано.** Разница MAE в 2–3% без
проверки значимости не является результатом.

**Накопитель управляется по прогнозу, а счёт выставляется по факту.**
Дополнительно считается вариант с идеальным прогнозом. Разница между ними —
денежная цена ошибки модели; именно она связывает прогнозную часть работы с
экономической.

## Экономическая модель накопителя

Трёхзонный тариф по действующему в России порядку (будни), ставки —
Москва, дома с газовыми плитами, с 01.07.2025:

| Зона | Часы | Тариф, руб/кВт·ч |
|---|---|---|
| Пиковая | 07–10, 17–21 | 11.24 |
| Полупиковая | 10–17, 21–23 | 7.87 |
| Ночная | 23:00–07:00 | 4.08 |

Пиковая зона — это утренний и вечерний максимумы потребления, а не середина
дня. В выходные и праздники пиковая зона не применяется. Значения задаются в
`config.py` (`RealWorldReference.TARIFF_*`).

Учитываются: односторонний КПД `√η` при заряде и разряде, стоимость деградации
за прокачанную энергию, ежегодные затраты на обслуживание, плата за мощность по
максимуму в пиковые биллинговые часы.

Стоимость деградации не задаётся константой, а выводится из капитальных затрат
и ресурса: `CAPEX / (ёмкость × глубина разряда × число циклов)`. При 25 000
руб/кВт·ч, DoD 80% и 6000 циклах это ≈5.2 руб/кВт·ч оборота — величина,
сопоставимая с тарифным спредом.

Инвертор питает только собственную нагрузку: отдать в сеть больше, чем
потребляется в этот час, невозможно, поэтому разряд ограничивается фактическим
спросом, а неиспользованная энергия остаётся в батарее.

Две стратегии управления:

* `tariff` — календарная: заряд ночью, разряд в пиковой зоне. Прогноз не
  использует, поэтому служит контрольной точкой.
* `peak_shaving` — порог срезки как квантиль прогноза на ближайшие 24 ч, разряд
  пропорционален превышению. Ошибка прогноза напрямую переходит в недобор
  экономии.

## Поведение при отказе модели

Падение одной модели не прерывает расчёт: остальные обучаются, и результаты
строятся по ним. Но такой запуск **не считается успешным**:

- в лог выводится «Пайплайн завершён ЧАСТИЧНО» с перечнем несостоявшихся
  моделей и текстом ошибки каждой;
- код возврата процесса — `2` (полный успех `0`, невозможность обучить хотя бы
  одну модель `1`);
- в `run_metadata.json` записываются списки `requested_models`,
  `trained_models`, `failed_models` и флаг `partial_failure`.

Так частичный отказ невозможно принять за полный результат — ни глазами по
логу, ни автоматически по коду возврата.

## Типы инференс-бандлов

Бандл собирается для победителя по валидации независимо от его типа, поскольку
лучшей регулярно оказывается не нейросеть:

| `model_kind` | Файл модели | Кто попадает |
|---|---|---|
| `keras` | `model.keras` | LSTM, VanillaTransformer, PatchTST |
| `sklearn` | `model.pkl` | Ridge, XGBoost, наивные базлайны |

В обоих случаях рядом лежат `scalers.pkl` со всеми скалерами и `config.json`
с длиной окна, горизонтом и числом признаков. Инференс через
`predict_from_bundle` строит те же 26 признаков тем же препроцессингом, что и
обучение, и отвергает вход неверной формы.

Keras-модели загружаются без восстановления оптимизатора: для прогноза он не
нужен, а его загрузка даёт предупреждение о несовпадении состояния. Дообучение
из бандла не предполагается.

import pandas as pd

bundle = load_model_bundle("results/models/PatchTST")

# DataFrame с теми же колонками, что отдаёт генератор,

## Тесты

```bash
python -m pytest tests/ -q
```

Покрыты: обучение скалеров только на train, непересечение входных окон с
целевыми значениями, реконструкция непрерывного прогнозного ряда, поведение
метрик на аналитически известных значениях, тарифный календарь, физика и
экономика накопителя, цикл экспорт → загрузка → инференс для всех типов
моделей, строгость экспортируемого JSON, поведение при частичном отказе и
устойчивость вывода к однобайтовой кодировке консоли.

Переменные окружения не требуются. Если в системе установлен конфликтующий
сторонний плагин pytest, автозагрузку плагинов можно отключить:

```bash
set PYTEST_DISABLE_PLUGIN_AUTOLOAD=1
```

## Ограничения

Эти границы применимости стоит указать и в тексте работы.

* **Данные синтетические.** Генератор физически осмыслен, но не заменяет
  реальные измерения. Перенос выводов на реальную сеть требует проверки на
  открытых данных (UCI Individual Household Electric Power Consumption,
  ENTSO-E Transparency Platform).
* **Плата за мощность применяется ко всей агрегированной нагрузке города.**
  Это упрощение: в действительности тариф зависит от категории потребителя и
  условий договора, поэтому абсолютные суммы экономии следует трактовать как
  оценку порядка величины.
* **Годовая экономия экстраполируется с одного 30-дневного окна.** Сезонность
  потребления при этом не учитывается.
* **Гиперпараметры подобраны вручную.** Систематический поиск (grid/Optuna) не
  проводился; ablation study запускается отдельно и в основной прогон не входит.
