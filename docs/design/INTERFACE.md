# Веб-интерфейс: экраны, слова, сценарии

Сведено из трёх независимых предложений (сценарии, визуальная система,
техническая реализация) и рецензии на них, 28.09.2026. **Пересмотрено
29.09.2026** после отзыва владельца («враждебный, ничего не понятно») и
отдельного разбора: полоса шагов, разделение навигации на расчёт и
исследование, тексты простым языком, пояснения терминов по клику. **Третья
редакция 29.09.2026**: мнемосхема вместо шагов, выводы функциональной
проверки и бизнес-разбора (выбор прогноза на отдельном отрезке, риск часа
пика, финансы, отчёт и Excel, «трудные» выгрузки). Визуальные правила —
в `VISUAL_SYSTEM.md`. Любой новый экран или элемент сверяется с этими двумя
файлами; отступление от них записывается сюда с причиной.

## Для кого

1. **Энергетик** промышленного или коммерческого потребителя 4–6 ценовой
   категории либо сбытовой компании. Знает тарифы и АСКУЭ, не знает машинного
   обучения. Вопросы: можно ли доверять моим данным; сколько сэкономит
   накопитель и когда окупится; что будет, если ставки изменятся; какой будет
   нагрузка завтра.
2. **Комиссия на защите** — семь минут показа (сценарий ниже).
3. **Исследователь** (автор работы) — сравнение моделей по прогонам.

## Ограничения, которые определяют интерфейс

- Модель прогонов прогнозирует только ряды, на которых обучалась. Для
  выгрузки нового клиента прогноз модели недоступен — экономика считается на
  простых прогнозах («как вчера», «как неделю назад», профиль часа недели).
  Поэтому «Экономия» идёт сразу после «Данных», а «Прогноз» работает с
  рядами прогонов.
- Квантильных моделей в текущих прогонах нет. Коридор прогноза показывается,
  только если `models/manifest.json` содержит `quantile_models`.
- Час пика субъекта оценивается по нагрузке самого объекта. Это допущение
  всегда названо.
- Годовая экономия — пересчёт периода. Меньше 14 суток — годовая цифра не
  показывается, только «за период».

## Навигация

Верхняя полоса-щит: знак опоры и «Smart Grid / расчёт накопителя» · рабочие
разделы **Данные · Экономия** · через вертикальную линию, приглушённо,
**Исследование: Прогноз · Модели** · справа табличка текущего файла со ссылкой
«сменить». На «Данных» и «Экономии» под полосой — **мнемосхема**: Сеть и
тариф → Приборы учёта → Предприятие → Накопитель. У каждого узла лампа и
одна строка состояния («3 из 6 можно считать», «максимум 3 273 кВт·ч за час»,
«5,43 млн ₽ в год»); узел — ссылка на свой экран. Шина между сделанными
шагами «под напряжением». Последняя загрузка запоминается в браузере, чтобы
переход в «Исследование» и обратно её не терял.

## Экраны

### Данные — одна страница, три состояния

1. **Пусто.** Заголовок-вопрос, три шага работы, зона загрузки с сеткой
   «7 дней × 24 часа» (по ней при перетаскивании бежит волна), [Выбрать файл],
   [Посмотреть на примере]. Принимаются CSV и Excel (.xlsx) до 50 МБ;
   двоичный файл другого вида отклоняется с причиной.
2. **Разбор.** Первые 10 строк как в файле. Найденные настройки — все можно
   исправить: кодировка, разделитель, десятичный знак, столбец времени,
   широкий или длинный формат, шаг. Два обязательных выбора без значения по
   умолчанию:
   - «Значения: средняя мощность за интервал, кВт / энергия за интервал, кВт·ч»;
   - «Время в строке: начало / конец интервала».

   Под переключателями — проверка обоих вариантов: «если кВт: 12.03 —
   18 400 кВт·ч за сутки, максимум 1 020 кВт·ч в 10:00; если кВт·ч: 36 800».
   Ошибка «вдвое» видна до расчёта. Ответить можно клавишами 1–4. Шапка
   отчёта над таблицей, дата и время в разных столбцах, ISO-даты, «24:00»,
   тонкий пробел в разрядах и пустые столбцы определяются сами и названы
   заметкой. Шаг — 5, 10, 15, 30 или 60 минут. [Прочитать].
3. **Отчёт.** Заключение одной строкой («Пригодны 4 из 6 приборов; у ТП-7 Ф-4
   застывшие показания»). Таблица: прибор · период · полнота · заключение;
   строка раскрывается в детали (пропуски, самый длинный разрыв, неполные
   часы, повторы, отрицательные, нули до подключения, застывшие, нетипичные
   часы — последние «для сведения»). График выбранного прибора с отметками
   проблемных часов под осью; над графиком — ковёр «сутки × час» за весь
   период, клик по суткам открывает их на графике. Расход по месяцам с полем
   «по счёту» и расхождением (больше 3 % — красным). [Посчитать экономию] ·
   [Изменить, как читать файл] · [Загрузить другой файл].

Строки без даты («Итого» внизу) отбрасываются с сообщением «Пропущена 1
строка без даты». Столбцы «Итого / Всего / Сумма» исключаются автоматически.

### Экономия — параметры слева, результат справа

**Параметры** (288 px, сворачиваются): «Считать по» — сумма выбранных
приборов или один прибор; ценовая категория 3–6 (ставки, не относящиеся к
категории, скрыты); ставки с единицами в подписи; плановые часы пиковой
нагрузки СО — шкала суток из 24 ячеек; накопитель — цена за кВт·ч и мощность
в процентах от пика (по умолчанию 20 %, ёмкость — 4 часа этой мощности);
[Рассчитать]. Поле с примерным значением помечено «пример»; правка снимает
пометку, для остальных — одна кнопка «Все ставки верны».

Пустая ставка своей категории или пустые часы пика — ошибка, а не
молчаливая подстановка примера. Мощность накопителя 1–100 %, цена
1 000–200 000 ₽/кВт·ч. Период — общий для выбранных приборов; немногие
сутки с пропусками (до 10 %) исключаются и перечисляются в паспорте, где
«как вчера» не на что опереться — берётся профиль часа недели.

**Результат**, сверху вниз, без вкладок (актуальный порядок):

1. Итог со шкалой прибора и «Средние рабочие сутки», под ним [Отчёт для
   печати] и [Выгрузить в Excel].
2. «Если час пика региона окажется другим»: как в расчёте / любой плановый
   час в среднем / самый неудачный.
3. «Вложение за срок службы»: ставка дисконтирования, срок службы, рост
   тарифов — NPV с разбросом, IRR, дисконтированная окупаемость, график
   накопленного потока. Пересчёт мгновенный, без повторного расчёта.
4. Паспорт, составляющие, сравнение прогнозов (с отрезком выбора), работа
   накопителя, по месяцам, «что если».

Ниже — исходное описание первой версии, пункты которого остаются в силе:

1. **Итог.** «Чистая экономия в год» — число и под ним полоса разброса с
   подписями краёв; строка «при планировании по прогнозу „профиль часа
   недели“»; «Окупаемость 9–14 лет» (капзатраты / верхний и нижний край
   годовой экономии). Нижний край ≤ 0 — «в неблагоприятном варианте экономии
   нет». Паспорт расчёта — до пяти строк, только сработавшие условия.
2. **Из чего складывается.** Энергия (подпись: «минус потери на заряд и
   разряд»), мощность (покупка), сетевая мощность, отклонения от плана
   (категории 5–6), износ, обслуживание — со знаками, столбики от нуля.
3. **Сравнение прогнозов.** «Как вчера», «как неделю назад», «профиль часа
   недели», модель (если ряд ей известен), «точный прогноз на сутки»,
   «потолок». Столбцы: ошибка, кВт·ч · за период, ₽ · в год, ₽ (разброс) ·
   доля потолка. Над таблицей — период: «по 61 суткам, 14.02–15.04».
4. **По месяцам** — столбики экономии, ₽.
5. **Что если** — три строки по одному фактору: ёмкость ×0,5 / ×1 / ×2; цена
   накопителя 12 / 16 / 24 тыс. ₽/кВт·ч; ставки мощности −30 / 0 / +30 %.
   Центр совпадает с итогом. Точка считается по клику, [Посчитать все 7] —
   фоном.

**Паспорт расчёта.** Слово слева («Данные», «Оценка», «Пример»), текст —
условие и действие. Строки «Оценка» и «Пример» — на фоне предупреждения.
Никаких цветных кружков и значков.

- Данные · Период 61 сутки, 14.02–15.04, 6 приборов.
- Оценка · Пересчитано на год по 61 суткам; зима не вошла.
- Оценка · Час пика субъекта взят по вашей нагрузке; фактический час
  публикует АТС, экономия на покупной мощности может быть ниже.
- Пример · Ставки из примера — введите свои, строка исчезнет.
- Оценка · Меньше трёх недель данных — разброс ориентировочный.

**Долгий расчёт.** Одна строка: «Считаем: 3 из 7 · прошло 0:24» и
[Остановить]. Последний сохранённый результат остаётся на экране.

### Прогноз

Сверху: прогон (выпадающий список полных панельных), ряд, модель (по
умолчанию лучшая на валидации).

- **Следующие сутки** — если есть история и прогноз погоды (демо): фраза
  «30.09: максимум ≈ 840 кВт·ч в 11:00»; покрытие суток «24 из 24 ч» (при
  неполном — первый непокрытый час); график 7 суток факта и прогноза;
  таблица по часам, [CSV].
- **Проверка на истории** — факт и прогноз на тестовом отрезке прогона;
  «ошибка на 18 % меньше, чем у „как вчера“» (по MAE на тех же сутках).
- Коридор — только при квантильной модели, с подсказкой «на проверке факт
  был внутри в 78 % часов».
- Незнакомый ряд: «Модель прогона не знает этот ряд — прогноз не строится.
  Экономия по простым прогнозам — в разделе „Экономия“».

### Модели

Список прогонов: дата, режим, данные, сиды, статус (фигура и слово).
Прогоны smoke скрыты за флажком, неполные каталоги пропускаются. Страница
прогона: таблица моделей (ошибка, отношение к «как вчера», ± по сидам;
MASE — мелко, со своим именем), ряды от худшего, экономика по клиентам
(пик рядом с рублями, без суммы), [Открыть полную сводку прогона].

## Словарь

| В коде | В интерфейсе |

| verdict «пригоден» | можно считать |
| отрицательные значения | есть отрицательное значение — возможно, перепутан знак |
| пропуск N ч подряд | нет данных N ч подряд — возможно, прерывалась связь |
| застывшие показания | показания не менялись 6 ч и дольше — возможно, завис счётчик |
| outliers | необычные часы — на расчёт не влияют |
| coverage | есть данные, % |
| net_savings, в год | накопитель сэкономит в год |
| annual_lo…annual_hi | скорее всего от … до … |
| payback | окупится за (вложения ÷ экономия в год) |
| паспорт расчёта | на чём основан расчёт: Факт / Допущение / Нужно ваше значение |
| Оптимум при известном будущем | предел: вся нагрузка известна заранее |
| share_of_bound | от предела, % |
| Идеальный прогноз | точный прогноз на сутки |
| Naive24 / Naive168 / HourlyProfile | как вчера / как неделю назад / профиль часа недели |
| MPC day-ahead | план заряда на сутки вперёд по прогнозу |
| gen capacity / net capacity | покупка мощности / передача: содержание сетей |
| net energy rate / single rate | передача: оплата потерь / передача |
| deviation up / down | взяли больше плана / взяли меньше плана |
| peak_windows | часы пиковой нагрузки в регионе (публикует СО) |
| peak_hours_of_region | час пика региона — оценка |
| degradation / O&M | износ батареи / обслуживание |

Пояснения по клику («Что это?», `webapp/texts.py`): разброс, окупаемость,
ценовая категория, часы пика, покупка мощности, содержание сетей, предел,
план заряда, единицы в файле.

## Сценарий защиты, 7 минут

1. «Данные» → демонстрационный объект (30 мин, кВт, cp1251, «Итого»). Проверка
   вариантов показывает ловушку «вдвое». В отчёте ТП-7 Ф-4 — застывшие
   показания, ТП-12 Ф-1 — ошибка знака.
2. «Экономия» → результат из кэша: итог с разбросом, паспорт, сравнение
   прогнозов.
3. «Что если» → ставки мощности +30 %, пересчёт одной точки.
4. «Прогноз» → известный ряд, проверка на истории.
5. «Модели» → таблица по сидам, отрицательные результаты в сводке прогона.

Перед защитой кэш прогревается отдельной командой.
